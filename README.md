## О проекте

SinoDrive — веб-приложение базы знаний о китайском автомобилестроении. Оно связывает производителей, марки, модели, поколения и модификации автомобилей с их характеристиками, платформами и технологиями, а также с тематическими статьями, видеоматериалами и реестром источников.

Основные возможности:

- каталог марок и автомобилей с фильтрами по кузову, типу силовой установки, приводу, рынку и цене;
- страницы моделей и модификаций с характеристиками, фото и источниками;
- поиск по слову, словосочетанию и предложению (PostgreSQL Full Text Search и `pg_trgm`) с группами «Статьи», «Автомобили», «Технологии», «Видео» и результатами из интернета;
- исправление запроса (опечатки, неверная раскладка, русское написание марок) и прямые ответы на вопросы вида «самый быстрый электромобиль»;
- сравнение модификаций и объяснимый подбор автомобиля по правилам;
- роли Guest, User, Editor и Administrator, комментарии и избранное;
- импорт моделей из Wikidata с описаниями из Википедии и фото с Wikimedia Commons.

Стек: Python, Django, PostgreSQL, Bootstrap 5, pytest.

## Локальный запуск

Требуются Python 3.12+ и Docker.

Полный набор для защиты (проверено на пустой базе: 15 марок, 253 модели, 59 модификаций, 12 статей, 9 видео, 23 источника; импорт занимает около минуты и требует интернета):

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
docker compose up -d db
.venv/bin/python manage.py migrate
.venv/bin/python manage.py load_course_data
.venv/bin/python manage.py setup_roles
.venv/bin/python manage.py import_wikidata --publish
set -a; . ./.env; set +a
.venv/bin/python manage.py runserver
```

`import_wikidata --publish` добавляет 216 моделей из Wikidata с фото и описаниями из Википедии; без этого шага остаётся проверенный вручную набор из 37 моделей. Строка `set -a; . ./.env; set +a` передаёт Django ключ внешнего поиска из `.env` (см. ниже). Если Python сообщает `CERTIFICATE_VERIFY_FAILED`, перед импортом и запуском выполните `export SSL_CERT_FILE=/etc/ssl/cert.pem`.

`load_course_data` формирует полный набор для защиты (15 марок, 37 моделей, 59 модификаций, статьи, источники и 8 официальных роликов YouTube, которые запускаются прямо на странице по кнопке ▶) и сам вызывает `load_demo_data`. Для минимального набора из двух модификаций достаточно `load_demo_data`. Обе команды идемпотентны.

`setup_roles` создаёт или обновляет группы `Editor` и `Administrator` с правами Django. Чтобы пользователь вошёл в Django Admin как редактор, администратор отмечает у него «Статус персонала» и добавляет группу `Editor`. Редактор добавляет и изменяет данные, но не удаляет справочные сущности: они архивируются через `is_active` или статус статьи. Команду можно запускать повторно.

Если порт 5432 занят другой СУБД, задайте другой порт и для контейнера, и для Django, например `DB_PORT=5434 docker compose up -d db` и `export DB_PORT=5434`.

После загрузки demo-данных интерфейс доступен по <http://127.0.0.1:8000/>. Основные разделы: `/brands/`, `/cars/`, `/articles/`, `/technologies/`, `/search/`, `/compare/`, `/recommendations/`, справка `/guide/` («Общие сведения») и реестр источников `/sources/`.

Каталог `/cars/` фильтруется по марке, кузову, типу силовой установки, приводу, рынку и диапазону цены. Для цены нужна валюта; все условия уровня модификации проверяются на одной и той же модификации, а модели без указанной цены в ценовой фильтр не попадают. Каталог, марки, статьи и источники разбиты на страницы.

У марок и моделей есть необязательные поля `image_url` и `image_credit`: изображение хранится у внешнего источника, а в карточке показывается автор и лицензия. `load_course_data` проставляет свободно лицензированные фото всех 16 моделей и логотипы 7 марок с Wikimedia Commons (CC BY, CC BY-SA, CC0, public domain). Свободного логотипа Hongqi на Commons нет, поэтому его файл хранится в проекте (`static/img/brands/hongqi.png`). Поле `image_url` принимает либо внешнюю http(s)-ссылку, либо путь `/static/img/…` к файлу проекта. Для любой записи без изображения выводится нейтральная заглушка. Изображения загружаются браузером с `upload.wikimedia.org`, поэтому без интернета вместо них показываются подписи `alt`. Для демонстрации поиска подходят запросы `BYD` (слово), `Blade Battery` (словосочетание), `Какие электромобили BYD используют Blade Battery?` (предложение), `зикр 001` (исправление запроса) и `самый быстрый электромобиль` (прямой ответ из данных). Внешний поиск ждёт ответа Tavily до 3 секунд (`EXTERNAL_SEARCH_TIMEOUT_SECONDS`); при тайм-ауте внутренние результаты показываются полностью, а внешние появятся при повторном запросе.

Поисковые поля предлагают локальный autocomplete после двух введённых символов. JSON endpoint `/search/suggest/?q=...` не вызывает Tavily. Для демонстрации исправления опечаток используйте `Zeek 001` или `Balde Battery`: система предложит близкий термин, не меняя запрос автоматически.

Demo-команда создаёт два сопоставимых исполнения — BYD Seal «Увеличенный запас хода RWD» и Zeekr 001 «100 кВт·ч AWD». Для них заполнены силовые установки, размеры, динамика, батареи, электромоторы, трансмиссии, европейский рынок, комплектации с ценами в EUR, ADAS и технологии. Команда остаётся idempotent и безопасна для повторного запуска.

На странице `/compare/` эти модификации можно выбрать в двух списках и сопоставить по нормализованным характеристикам. Выбор передаётся параметрами `left` и `right`, поэтому ссылку на результат можно открыть повторно или отправить другому пользователю.

Страница `/recommendations/` выполняет stateless-подбор модификаций по GET-параметрам. К обязательным условиям относятся кузов, тип силовой установки, привод, рынок и бюджет; мощность, ёмкость батареи, технология и ADAS являются пожеланиями. Для бюджета обязательно выбираются рынок и валюта: конвертация валют не выполняется. Demo-команда добавляет редактируемые мягкие правила «запас хода не менее 500 км» и «мощность не менее 300 кВт». Для показа используйте сценарии `BEV + RWD`, `BEV + AWD` и невозможную комбинацию `ICE + AWD`.

### Внешний поиск

Текущая интернет-выдача использует официальный Tavily Search API. Перед запуском задайте переменные окружения:

```bash
export EXTERNAL_SEARCH_PROVIDER=tavily
export EXTERNAL_SEARCH_API_KEY=your-tavily-api-key
```

Запуск с переменными из `.env` и включённым внешним поиском:

```bash
set -a; . ./.env; set +a; .venv/bin/python manage.py runserver 8010
```

Если внешняя выдача пишет «временно недоступна», а в логе есть `CERTIFICATE_VERIFY_FAILED`, Python не видит корневые сертификаты; добавьте `export SSL_CERT_FILE=/etc/ssl/cert.pem` (macOS) или один раз выполните `Install Certificates.command` из папки Python.

Дополнительно при необходимости настраиваются `EXTERNAL_SEARCH_ENDPOINT`, `EXTERNAL_SEARCH_TIMEOUT_SECONDS`, `EXTERNAL_SEARCH_LIMIT` и `EXTERNAL_SEARCH_LANGUAGE`; для Tavily используются безопасные значения по умолчанию. Django не загружает `.env` автоматически: при ручном запуске переменные нужно экспортировать в окружение. Если провайдер или ключ отсутствует, приложение использует `NullExternalSearchProvider`: внутренний поиск продолжает работать, а сетевой запрос не выполняется.

Настройки читаются из переменных окружения. Список переменных приведён в `.env.example`; файл `.env` намеренно не отслеживается Git. Django не загружает `.env` самостоятельно, поэтому значения следует экспортировать в окружение или передать средствами IDE/контейнера. Для локального запуска без отдельного `.env` используются безопасно ограниченные development-значения, совпадающие с `compose.yaml`.

## Импорт моделей из Wikidata

```bash
.venv/bin/python manage.py import_wikidata --dry-run -v 2   # показать, что будет создано и что отсеяно
.venv/bin/python manage.py import_wikidata                  # создать новые модели черновиками
```

Команда запрашивает открытый SPARQL API Wikidata (данные CC0), фото с Wikimedia Commons (автор и лицензия сохраняются в `image_credit`) и вступления статей Википедии как описания (ссылка на статью и лицензия CC BY-SA сохраняются в `description_source_url`/`description_credit`; `--no-descriptions` отключает этот шаг). Если русской статьи нет, используется редакторский перевод английской статьи из `apps/cars/data/wikipedia_translations.json`. Ключ не нужен. Новые модели создаются с `is_active=False` и появляются на сайте только после проверки редактором в админке; флаг `--publish` сразу делает их активными, `--no-images` отключает запрос фото. Уже заполненные поля существующих моделей не перезаписываются, повторный запуск ничего не дублирует. Если Python установлен с python.org и сообщает `CERTIFICATE_VERIFY_FAILED`, укажите системный набор сертификатов: `export SSL_CERT_FILE=/etc/ssl/cert.pem`.


## Реализованные этапы

Этап 1 включает модели данных, Django Admin, миграции, demo-команду и модельные тесты. На этапе 2 добавлены внутренний PostgreSQL Full Text Search, `pg_trgm`, поиск слова/фразы/предложения, ранжирование и адаптивная выдача с группами `Articles`, `Cars`, `Technologies`, `Videos`. На этапе 3 реализованы `ExternalSearchProvider`, текущий адаптер Tavily Search API, дополнительный адаптер Brave Search API, `NullExternalSearchProvider` и отдельная группа `External results`. На этапе 4 добавлены единый Bootstrap 5 layout, главная, каталоги и detail pages марок, моделей, модификаций, технологий и статей, базовые фильтры и пользовательская аутентификация. На этапе 5 реализовано stateless-сравнение двух модификаций через GET-параметры. На этапе 6 добавлен детерминированный rule-based подбор с объяснениями, процентным score и явно обозначенными частичными совпадениями.

Зарегистрированные пользователи могут комментировать статьи и добавлять модели и статьи в «Избранное» (`/accounts/favorites/`); статьи фильтруются по категориям и тегам. Дополнительно реализованы справка «Общие сведения», публичный реестр источников, изображения марок и моделей, фильтры по рынку и цене, пагинация списков и роли `Editor`/`Administrator`. Автоматические тесты покрывают подбор, сравнение, каталог, роли и набор `load_course_data`.

Следующими задачами остаются сравнение трёх-четырёх модификаций, раздельная пагинация групп поиска и Playwright-сценарии.
